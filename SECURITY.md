# Security policy

This repository is at bootstrap stage. Reports about the default branch and
repository automation are welcome; there are no supported application releases
or established backport or response-time commitments yet.

## Report privately

Do not post vulnerabilities, exploit details, credentials or private data in
public issues or pull requests. Private vulnerability reporting is enabled:
[Report a vulnerability](https://github.com/DaasaVaani/library/security/advisories/new).

If that route is unavailable, open only a neutral issue titled "Private security
contact requested", with no vulnerability details, logs, secrets or proof of
concept. Request an approved private channel and wait before sharing details.
That public contact request is not a private vulnerability report.

Include affected commits/components, sanitized reproduction steps, impact and
suggested mitigation in the private report. Coordinate disclosure with
maintainers; do not access other people's data or test without authorization.
Revoke or rotate exposed credentials you control promptly. Removing a secret
from Git history alone does not make it safe.

For confidential content-rights evidence, request an approved private channel
without attaching evidence publicly; security advisories are for vulnerabilities.

Maintainers should assess reports privately, coordinate fixes and verification,
and define supported versions before releasing applications or tooling.
